# HIBEYA Akal Budi — Content Governance

Version: 1.0

## Content Lifecycle

Every activity should progress through:

IDEA
→ DEVELOPMENT OBJECTIVE
→ CONTENT DESIGN
→ ORIGINALITY REVIEW
→ CULTURAL REVIEW
→ WELLBEING REVIEW
→ ACCESSIBILITY REVIEW
→ TECHNICAL VALIDATION
→ PLAY TEST
→ APPROVAL
→ PUBLISH
→ OBSERVE
→ IMPROVE

No content should bypass this lifecycle merely because it can be generated
quickly.

## Development Objective

Every activity must answer:

What is the child practising?

Why is this suitable for the intended age band?

What observable behaviour demonstrates successful engagement?

What should happen after the digital activity?

## Learning Domains

Initial supported domains:

- numeracy
- language
- memory
- logic
- social
- life-skill

Future domains should be added only after the domain model is reviewed.

## Developmental Evidence

Content should be evidence-aligned.

Acceptable evidence references may include:

- recognised child-development guidance
- early-childhood education frameworks
- peer-reviewed research
- curriculum standards
- professional educator review
- structured internal play testing

Akal Budi must not use the word "proven" where only a plausible educational
rationale exists.

## Play First

The child should experience:

curiosity
→ exploration
→ attempt
→ feedback
→ understanding

rather than:

instruction
→ pressure
→ test
→ score
→ punishment

## Difficulty

Difficulty must increase primarily through cognitive complexity rather than:

- smaller buttons
- faster timers
- visual clutter
- misleading controls
- intentionally frustrating interactions

## Malaysia Review

Where an activity claims Malaysian relevance, reviewers should consider:

- factual accuracy
- regional diversity
- cultural sensitivity
- linguistic authenticity
- contemporary relevance
- avoidance of stereotypes
- appropriate representation

Malaysia-related content must not invent historical, cultural or religious
facts merely for entertainment.

## Sensory Load

Every activity receives a sensory-load classification.

LOW:
mostly static elements, restrained audio, minimal animation

MODERATE:
limited animation or richer audio with clear educational purpose

HIGH:
not permitted in the initial Akal Budi child experience without explicit
review

## Screen-to-World Design

Activities should be assessed for whether a useful offline extension is
appropriate.

An offline extension should:

- require little or no purchase
- be safe for the intended age
- involve common household or outdoor objects where possible
- encourage conversation, movement, observation or creation

## Feedback

Positive feedback should acknowledge effort or successful thinking.

Avoid exaggerated reward loops.

Preferred:

"Betul!"

"Bagus mencuba."

"Jom cuba sekali lagi."

Avoid:

"JANGAN BERHENTI!"

"Main lagi untuk kekalkan streak!"

"Anda akan kehilangan hadiah!"

## Parent Value

The parent experience should eventually explain:

- skill practised
- activity completed
- estimated learning time
- suggested real-world extension
- areas that may benefit from further practice

Progress information must not imply medical or developmental diagnosis.
